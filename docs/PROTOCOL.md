# Протокол платформенного интерфейса MECHREVO Jiaolong MRID6

Восстановлен 21.11.2026 статическим чтением штатной программы «蛟龙游戏控制中心» (Shenzhen Bitland Information Technology,
`C:\Program Files (x86)\蛟龙游戏控制中心\`) на этой же машине и проверен на железе. Код вендора не запускался и не копируется —
здесь только факты об интерфейсе, нужные для совместимого приложения.

Машина: MECHREVO Jiaolong Series MRID6 (плата `MRID6-23`, BIOS Insyde `MRID6_23_V36`), Ryzen 9 7845HX, RTX 4070 Laptop.

## Транспорт

* WMI: пространство `root\WMI`, класс `MICommonInterface`, экземпляр `InstanceName='ACPI\PNP0C14\MIFS_0'`
  (устройство `PNP0C14` «MIFS» — WMI-мост ACPI Bitland).
* Метод `MiInterface(InData: uint8[32], out OutData: uint8[30], out Reserved: uint16) -> bool`.
* Нужны права администратора (иначе «Отказано в доступе»).
* Хоткеи — событие `SELECT * FROM HID_EVENT20` (`root\WMI`), поле `EventDetail: uint8[]`.

## Формат запроса `InData` (32 байта, остальное нули)

| байт | смысл |
|------|-------|
| 0    | 0 |
| 1    | тип: `0xFA` — Get, `0xFB` — Set |
| 2    | 0 |
| 3    | код команды |
| 4…   | аргументы (для Set) |

Ответ `OutData`: `[1]=0x80`, `[3]=код`, значение с `[4]`.

## Команды

| код | имя | Get | Set |
|-----|-----|-----|-----|
| 0x08 | SystemPerMode | `[4]`: 0 баланс, 1 производительность, 2 тихий | `[4]` |
| 0x09 | GPUMode | 0 гибрид, 1 дискретная (MUX; нужна перезагрузка) | `[4]` |
| 0x0A | RGBKeyboardStatus | ? | — |
| 0x0B | FnLock | 0/1 | `[4]` |
| 0x0C | TPLock (тачпад) | 0/1 | `[4]` |
| 0x0D | CPUGPUFanSpeed | `cpu = [4]\|[5]<<8`, `gpu = [6]\|[7]<<8` — **об/мин** | — |
| 0x0F | Ambientlight (периметр) | 0/1 | `[4]` |
| 0x10 | RGBKeyboardMode | 1 радуга, 2 фикс. цвет | `[4]`; **на этой плате принимаются только 1 и 2** — записи 0 и 3 игнорируются (проверено), «выкл» = яркость 0 |
| 0x11 | RGBKeyboardColor | `[4..6]` = R,G,B | `[4..6]`; штатная программа пишет `0x10=2`, ждёт **500 мс**, затем цвет |
| 0x12 | RGBKeyboardBrightness | 0…3 (0 = подсветка погашена в любом режиме) | `[4]` |
| 0x13 | SystemAcType | 1 Type-C, 2 круглый разъём | — |
| 0x14 | MaxFanSpeedSwitch | 0/1 — фиксированные обороты вкл/выкл | `[4]` |
| 0x15 | MaxFanSpeed | `[4]` — **процент** оборотов (0…100) при включённом 0x14 | `[4]` |
| 0x16 | CPUThermometer | `[4]` — температура CPU, °C (совпадает с ACPI `TZ01`) | — |
| 0x17 | CPUPower | всегда 0 (состояние не читается) | `[4]=состояние`, `[5]=значение` |

### 0x17 CPUPower (лимиты питания CPU)

Состояние в `[4]`: `0` выкл, `1` вкл («свои лимиты»), `2` SPL, `3` SPPT, `4` температурная стенка.
Штатная программа включает режим и затем пишет три значения:

```
Set 0x17 [1]            ; включить
Set 0x17 [4, wall]      ; температурная стенка, °C   (диапазон UI 89…100, по умолчанию 99)
Set 0x17 [2, spl]       ; SPL, Вт                    (диапазон UI 95…105, по умолчанию 101)
Set 0x17 [3, sppt]      ; SPPT, Вт                   (диапазон UI 105…120, по умолчанию 105)
Set 0x17 [0]            ; выключить
```

Текущие значения прочитать нельзя (Get всегда 0) — их помнит сама программа (вендор — в `AppMachineInfo`, base64).
После смены режима/сна EC, вероятно, сбрасывает лимиты — приложение применяет их заново.

### Вентиляторы (замер на железе)

`0x15` задаёт процент при включённом `0x14`: 36 % → ≈3575 об/мин; 45 % → ≈4400; 60 % и выше → ≈5000 об/мин (потолок).
Ступенчатая разгонка/сброс занимает несколько секунд.

## События Fn-клавиш (`HID_EVENT20.EventDetail`)

`[0]` тип (1 = горячая клавиша), `[1]` имя события, `[2]` значение (для 26/32 — `[2]<<8 + [3]`).

| имя | событие |
|-----|---------|
| 4 AirPlane, 5 RGB brightness, 6 TouchPad, 7 Fn, 8 RGB mode, 9 CapsLk, 10 Ambient, 13 NumLk, 14 ScrLk |
| 15 | SystemPerMode (Fn+F10): 0 баланс, 1 производ., 2 тихий |
| 25 PanelRefreshRate, 26 CPUFanSpeed, 32 GPUFanSpeed, 33 WinKeyLock |

Переключение режимов выполняет сам EC; штатная утилита `BLDFnHotkeyUtility` только показывает OSD. Приложение лишь отражает состояние.

Замечания (проверено на железе):

* Каждое событие приходит **дважды** подряд — нужен фильтр дублей (приложение отсекает одинаковые в пределах 400 мс).
* События приходят и на **программные** записи (то же `name=15` при `Set 0x08`), так что отличить нажатие клавиши от записи нельзя.
* `name=5` — яркость 0…3, `name=10` — Ambient 0/1, `name=7` — Fn-lock, `name=6` — тачпад.

## Конфликты с другим ПО

G-Helper (ASUS) и штатная программа вендора пишут в тот же состав настроек. При запущенном G-Helper в тесте режим производительности
самопроизвольно сбрасывался в «Баланс»; после закрытия G-Helper полный прогон (49 проверок) прошёл без единого сбоя. Держите запущенной
только одну программу управления.

## Офсет частоты GPU

Штатная программа использует NVAPI (P-state 0, `KaronOC.dll`: `Get/ChangePstatesLevel0Settings`). В приложении не реализовано
(слайдер вендора 0…200, значение 100 = без смещения → смещение ±100 МГц).

## Источники температур

* CPU: команда `0x16` (EC) или ACPI `MSAcpi_ThermalZoneTemperature` (root\WMI, тоже от администратора). Покоординатно/по ядрам
  не отдаётся — у вендора для этого `LibreHardwareMonitorLib`.
* GPU: NVML (`nvml.dll`, из драйвера NVIDIA).
