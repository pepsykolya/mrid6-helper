# Журнал MRID6 Helper

Новое сверху.

## 2026-11-21 — 0.2.1 (вторая порция замечаний)

* «Все режимы через секунду прыгают на ракету» — причина найдена: «свои лимиты» = режим 1 на плате, а приложение после каждой смены
  режима заново применяло лимиты (`DelayedReapply`) → снова «Производительность». Проверено на железе: `S 17 01` → режим 1,
  `S 17 00` возвращает прежний; запись режима при открытых лимитах их не закрывает.
  Исправлено: лимиты по умолчанию выключены и не сохраняются; выбор режима (окно, трей, Fn+F10) сначала снимает лимиты, затем пишет
  режим; автоповтор убран; при старте шлётся `S 17 00` (безвреден при закрытых лимитах).
* «Радуга не меняется, горит красным» — плата в режиме 1 цвет не анимирует (регистр `0x11` не меняется за 12 с). Сделана программная
  плавная радуга (режим 2 + перебор оттенка, круг ≈ 14 с); «Авто-режим платы» оставлен отдельным пунктом.
* Плата игнорирует смену режима сразу после записи цвета → повтор с паузой и проверкой.
* Самотест 56/56 (добавлены: лимиты по умолчанию выключены, лимиты→режим 1, выбор режима при лимитах держится 3,5 с, радуга меняет цвет,
  радуга останавливается), точное восстановление исходного состояния.

## 2026-11-21 — 0.2.0 (по замечаниям владельца)

* Жалобы: «радуга не срабатывает», «галочки не проставляются», «значок в игровом режиме оранжевый, но через секунду красный».
* Радуга: запись доходила (читается обратно), но при яркости 0 подсветка погашена в любом режиме → при выборе режима яркость
  поднимается до 3; режимы 0 и 3 плата игнорирует → «Выкл» теперь = яркость 0, список Выкл/Радуга/Один цвет; цвет пишется через
  500 мс после режима (как у вендора).
* Галочки: стандартный `CheckBox` с `FlatStyle.Flat` на тёмной теме не показывал отметку → свой `ToggleBox` (синий с белой галочкой).
* Значок: цвет брался из температуры (≥90 → красный). Теперь цвет по режиму (оранжевый в «Производительности»), перегрев — красная рамка.
* Опрос состояний платы раз в ~3 с + «окно тишины» 2,5 с после действий пользователя: окно отражает Fn-клавиши и не показывает устаревшее.
* События Fn приходят по два раза → фильтр дублей 400 мс.
* Самотест `--selftest` (49 проверок). Первый прогон: 44/47, найдено: (1) «Выкл» плата не принимает; (2) режим производительности
  самопроизвольно падал в «Баланс» в 13:50:20. Гипотеза владельца — мешает запущенный G-Helper. Проверено: G-Helper закрыт → режим
  держится на каждом этапе, 49/49. Вывод: G-Helper на этой плате использовать нельзя (README).
* Версия 0.2.0 (AssemblyInfo).

## 2026-11-21 — первый рабочий выпуск 0.1

* Запрос владельца: «маленькое приложение типа G-Helper» для Jiaolong MRID6 с температурами и полной поддержкой ноутбука.
* Разведка: на машине стоит «蛟龙游戏控制中心» (WPF/.NET 6) + `BLDHotKeyService` + `BLDFnHotkeyUtility`. Через .NET-метаданные
  (самодельный IL-дизассемблер на `System.Reflection.Metadata`, без запуска чужого кода) восстановлен протокол: WMI
  `root\WMI : MICommonInterface.MiInterface`, команды 0x08…0x17, события `HID_EVENT20`. Всё — в `docs/PROTOCOL.md`.
* Проверка на железе (UAC, только чтение): интерфейс отвечает, RPM читаются (CPU 3575 / GPU 3660), цвет подсветки и состояния верны.
* Замер вентиляторов (повышением %, исходное значение возвращено): 36 % → 3575, 45 % → 4400, ≥60 % → ~5000 об/мин.
* Найдено: при CPU 96 °C штатная программа держала «фиксированные обороты» 36 %. В приложении сделана защита (CPU ≥ 90 / GPU ≥ 88 → 100 %).
* Сборка: C# WinForms под .NET Framework 4.8, Roslyn из VS BuildTools, `build.ps1`; без загрузок.
* Исправлено в ходе проверки: (1) раскладка с фиксированными высотами резала подписи → авторазмер групп по реальной высоте;
  (2) при закрытии в настройки писалось состояние вентиляторов из железа, и оно навязывалось при следующем старте → теперь
  пишется только явный выбор; (3) защитный разгон не снимался при выходе → снимается.
* Не сделано: офсет частоты GPU (у вендора NVAPI), покоординатные температуры CPU, per-key RGB, график оборотов.
* Проверить с владельцем на нажатиях: Fn+F10, Fn+F9 (события пишутся в `app.log`).
