## 2026-11-21 — 0.4.1: мультиязычность, исправление «окно открывается само»

* «После закрытия крестиком сворачивается в трей, но секунд через 30 снова открывается само» — причина: наблюдатель раз в минуту запускает
  `Mrid6Helper.exe --tray --watchdog`; вторая копия видит, что программа уже работает, и посылала ей сигнал «показать окно» (нужен ярлыку, но не
  наблюдателю). Теперь копия с `--watchdog` молча выходит; окно показывает только ручной запуск/ярлык.
* «Нужна поддержка мультиязычности» — русский (исходный), English, 中文(简体). Реализация: `src/Lang.cs` (автогенерация `tools/gen_lang.py` из
  `tools/translations.py`), все русские литералы интерфейса обёрнуты в `L.T(...)` (лексер C# `tools/cslex.py` — без регулярок по тексту);
  ключ — русский текст, незнакомый ключ возвращается как есть. Язык: авто (по `CurrentUICulture`: ru/uk/be/kk → ru, zh → zh, иначе en), выбор
  в «Система», ключ `--lang`. Смена языка применяется после перезапуска (подписи строятся при старте) — программа предлагает перезапуститься
  сама (`schtasks /Run Mrid6Helper-Open`). Самотест по умолчанию на русском. Генератор падает, если у строки интерфейса нет перевода.
* Служебные тексты (диагностика, описание задач планировщика, сообщения об ошибках) переведены на английский — их присылают в отчётах.
* Скриншоты для английского и китайского README; колонки значений датчиков шире, высота групп пересчитывается через 3 с (иероглифы переносили
  «1755 MHz» после расчёта и подрезали график).
* При старте цвет подсветки приводится к сохранённой яркости (после тестов в регистре оставалось приглушённое значение).

## 2026-11-21 — 0.3.4: плавность только ползунком, воспринимаемая яркость

* «Плавная подсветка по зажатым кнопкам работает плохо — убери, оставь плавную регулировку только ползунком; максимальная включается уже с третьей
  четверти ползунка». Удалён плавный ход по удержанию Fn (HandleFnBrightness/таймер/StartRamp…): клавиши шагают по ступеням платы, ползунок показывает ступень.
* Причина «максимум с 75 %»: яркость масштабировалась линейно по световому потоку, а глаз воспринимает нелинейно (≈ гамма 2), плюс ступени
  платы по вендору 0/40/70/100 %, а не равные трети. Теперь ползунок = воспринимаемая яркость: световой поток = (ползунок/100)², берётся
  наименьшая ступень платы {0,40,70,100 %}, которой хватает, остальное — масштаб цвета. 75 % ползунка → поток 0,56 → ступень 70 % и цвет ×0,80
  (не максимум); 100 % — ступень 3 без ослабления. Положение ползунка для ступеней платы: 63 / 84 / 100 %.
* Самотест 83/83 (проверки 50 % / 75 % / 100 %, ступени от клавиш).

## 2026-11-21 — 0.3.3: профиль «Свой» на «Производительности» со сниженными лимитами, плавная яркость

* «Для профиля свой — «Производительность» как отправная точка, но уменьшать свои лимиты питания». Значения ниже диапазона вендора плата
  принимает (A/B-замер: SPL 60/SPPT 70/стенка 85 → производительность CPU 43 % против 99 %). Ползунки расширены (SPL 50–105, SPPT 60–120,
  стенка 80–100, SPPT ≥ SPL + 5), умолчания профиля: база «Производительность», лимиты включены, SPL 82 / SPPT 92 / стенка 90
  (SettingsVer=2 мигрирует старые настройки). Вендорный SPL 82 из `Window_Loaded` использован как ориентир.
* «Яркость нельзя менять плавно; при зажатой Fn+F9 нужен плавный подъём, ступени — по нажатиям». Плата умеет 4 ступени (0–3), события
  `name=5` приходят на каждый шаг (удержание даёт цикл 0→1→2→3→0 или вниз). Яркость стала виртуальной 0–100 %: ступень платы
  `ceil(vb/33,3)` + множитель цвета в регистре `0x11`; ползунок 0–100 %; радуга умножается на тот же множитель. Одиночное событие =
  ступень; второе событие в пределах 700 мс = удержание → таймер 50 мс двигает яркость ≈ 50 %/с (направление по циклу уровней), останов
  через 900 мс без событий. Свои записи ступени отсеиваются окном 250 мс. Цвет и яркость сохраняются (KbColor, KbVb).
  Журнал Fn-событий теперь с миллисекундами (`t=`) — по нему можно подобрать пороги, если у платы другой ритм автоповтора.
* «Окно запустилось не по высоте экрана» — штатный запуск проверен в физических пикселях (1540 из 1540) и из трея, и ярлыком; вероятно,
  видели окно самотеста (он не растягивался). Самотест и `--shot` теперь запускаются свёрнутыми без значка на панели задач; растяжка
  повторяется через 0,5 с и берёт экран по положению курсора (после смены масштаба/монитора размер мог пересчитаться).
* Самотест 82/82; новые проверки: ступени 0/33/66/100 %, масштаб цвета при 50 %, имитация нажатия и удержания Fn.
* Находка: при завершении самотеста наблюдатель сразу поднимает обычную копию программы (ручной/тестовый запуск снимает метку выхода).

## 2026-11-21 — замер потолка оборотов (вопрос владельца «5000 — это максимум?»)

* Нет. При фиксированных 100 %: «Тихий» ≈ 3500–3700, «Баланс» ≈ 5000, «Производительность» ≈ 5800 об/мин. Раннее утверждение «потолок 5000»
  было ошибкой выборки (замер шёл в «Балансе»). Следствие для «Свой»: базовый режим «Тихий» физически ограничивает охлаждение ≈ 3600 об/мин
  даже при 100 % — на жаре брать «Баланс» или «Производительность» (подсказка добавлена в окно).

## 2026-11-21 — 0.2.1 (вторая порция замечаний)

* «Все режимы через секунду прыгают на ракету» — причина найдена: «свои лимиты» = режим 1 на плате, а приложение после каждой смены
  режима заново применяло лимиты (`DelayedReapply`) → снова «Производительность». Проверено на железе: `S 17 01` → режим 1,
  `S 17 00` возвращает прежний; запись режима при открытых лимитах их не закрывает.
  Исправлено: лимиты по умолчанию выключены и не сохраняются; выбор режима (окно, трей, Fn+F10) сначала снимает лимиты, затем пишет
  режим; автоповтор убран; при старте шлётся `S 17 00` (безвреден при закрытых лимитах).
* «Радуга не меняется, горит красным» — плата в режиме 1 цвет не анимирует (регистр `0x11` не меняется за 12 с). Сделана программная
  плавная радуга (режим 2 + перебор оттенка, круг ≈ 14 с); «Авто-режим платы» оставлен отдельным пунктом.
* Плата игнорирует смену режима сразу после записи цвета → повтор с паузой и проверкой.
* Самотест 56/56 (добавлены: лимиты по умолчанию выключены, лимиты→режим 1, выбор режима при лимитах держится 3,5 с, радуга меняет цвет,
  радуга останавливается), точное восстановление исходного состояния.
